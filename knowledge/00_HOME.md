# CENTRAL — Management Home

> McKinsey-inspired operating discipline, not an official McKinsey template.

## Value agenda

CENTRAL exists to turn verified information into faster, safer execution across existing projects. Technology is subordinate to outcomes.

### Active value streams

1. **Reliability** — PC, Ollama/Qwen, Git, Supabase, Vercel and controller loop remain healthy and recoverable.
2. **PowerLux Growth** — convert existing leads, partnerships, events and product assets into measurable value.
3. **PowerTV Distribution** — improve the existing PowerTV catalog/editorial/distribution system without rebuilding it.
4. **Vendetta Execution** — close date, venue, rights, matchup, sponsor and content gates for the 7 Nov 2026 planning window.

## Decision rights

- **Human** — final accountability for publication, external messages, contracts, spending, credentials/auth and production promotion.
- **ChatGPT Controller** — verifies current facts in connected systems, resolves contradictions, prepares safe repository/content changes and reviews local-agent output.
- **Qwen 4B** — local bounded analyst; proposal authority only.
- **Qwen 1.7B** — fast critic/planner; advisory only and never a single point of failure.
- **CENTRAL** — queue, provenance, heartbeat, handoff and execution-state control plane.

## Knowledge rule

Every substantive project task must start from the canonical project `STATE.md` and end by deciding whether durable knowledge changed. Durable changes are updated through a normal reviewed Git change so Obsidian and Git history stay aligned.

Never promote an unverified model statement into canonical knowledge.

## Standard management questions

For every project, answer in this order:

1. **What value are we trying to create?**
2. **What facts are verified now?**
3. **What is the real bottleneck?**
4. **What decision is required?**
5. **What is the smallest next action?**
6. **Who owns it?**
7. **How will we measure whether it worked?**
8. **What evidence would make us change course?**

## Anti-patterns

- no website rebuilds, replicas, mockups or parallel frontends for existing PowerLux/PowerTV
- no duplicated CRM or catalog when an existing system already owns the data
- no unverified claims copied from AI output
- no open-ended work without a value stream, owner and next action
- no destructive Git shortcuts to resolve routine drift
